# Knowledge Return — EXP015–020 reusable reality loop

## experiment
Read Human-owned repositories as reference only, extract one reusable mechanism from each, and prove or disprove the mechanism inside SandFrog without copying source authority.

## hypothesis
Useful system capabilities can be reused independently from the authority, identity, and constitutional meaning of the system they came from.

## worked
Six bounded mechanisms survived real SandFrog probes:

1. **MOMO — deterministic source → derived view**
   - Keep source identity / digest with the projection.
   - A view can be reproducible and drift-detectable without becoming a second authority.

2. **KIBI — bounded execution / authority envelope**
   - Technical capability does not imply authorization.
   - Repo / operation / path boundaries can reject possible-but-not-authorized work.

3. **KIJI — Git-resident restart checkpoint**
   - A fresh worker can recover the next action from durable repository evidence without chat history or Human relay.

4. **INNU — evidence → disposition without self-acceptance**
   - A successful probe may produce a machine-readable disposition while remaining distinct from independent acceptance.

5. **SARU — capability validation ladder**
   - `DOCUMENTED` is not `VERIFIED`.
   - Capability claims advance only after the required real probe succeeds.

6. **MOMO-Observatory — read-only observatory + drift detection**
   - Aggregate state can expose missing / drifting evidence without turning observed `next` information into execution authority.

All six were kept in SandFrog as small executable/probeable mechanisms rather than copied prose.

## surprise
The most useful thing to copy was not each source system's structure. It was the small operational seam that made its behavior recoverable or falsifiable.

The source repositories' authority models were deliberately *not* inherited. Reuse remained possible precisely because capability and authority were separated.

## reusable_pattern
A compact reusable Reality Loop Kit emerged:

```text
project
→ bound
→ checkpoint
→ decide
→ verify capability
→ observe
```

Meaning:

- **project** — produce a deterministic derived view with provenance;
- **bound** — state what execution is authorized;
- **checkpoint** — leave durable state that a fresh worker can resume;
- **decide** — turn evidence into an explicit disposition without self-ratification;
- **verify capability** — distinguish claims from measured reality;
- **observe** — expose state / drift without taking execution authority.

## what_not_to_copy
Do not infer that reuse grants the source system's authority.

The campaign intentionally did not copy:

- MOMO / MOMO-Observatory System-wide semantic authority;
- KIBI Protocol identity or ratification authority;
- KIJI / INNU / SARU role ownership;
- source-specific production branch semantics;
- Microsoft tenant / permission details;
- a full Cockpit, orchestrator, reviewer topology, or scheduler.

## possible_momo_implication
If MOMO evaluates these mechanisms, it can treat them as candidate implementation patterns rather than imported constitutional rules.

A useful adoption test would be:

> Does this mechanism preserve source ownership and Human authority while reducing reconstruction, recovery, or verification cost?

MOMO alone decides whether to accept, adapt, defer, or reject each mechanism.
